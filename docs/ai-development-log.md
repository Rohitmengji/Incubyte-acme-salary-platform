### Why AI help was useful here

- Building the first draft of a requirements document, ERD, sequence diagrams and ADRs quickly, from a long brief.
- Running registry and toolchain checks and a database spike before committing to the design, instead of relying on recalled facts.

### Decisions made after reviewing AI output

- **Same-origin API proxy ([ADR-0001](./adr/0001-same-origin-api-and-cookie-sessions.md)).** Cross-origin cookie auth between a Vercel web app and a separate API would break under third-party cookie blocking. Calling this out early avoided a late deployment surprise.
- **Pinned dependency versions.** Prisma 7.10, TypeScript 5.9 and TanStack Table 8.21, as described above.
- **CSV upload limit of 4 MB.** It's under Vercel's 4.5 MB request-body cap, so the deployment target is a constraint on the design.
- **Employee ID is supplied by HR, not generated.** It matches existing spreadsheets and makes double submits fail safely with a 409.

### Decisions made while reviewing AI output

- **No repository layer on top of Prisma.** Prisma's typed client already is the data-access layer, and one-to-one wrappers would add files without adding seams. [architecture.md §4](./architecture.md#4-backend-design) was updated to describe this honestly.
- **Seeded IDs are UUID v8**, derived from the employee code, so URLs stay stable when the database is rebuilt. `uuidv7()` is used for everything created at runtime.
- **The seed writes salary periods only for employees inserted in the same run,** in the same transaction. Re-runs never touch records edited through the app, and never trip the exclusion constraint.
- **The seed doesn't write audit rows.** Seeding isn't a user action, and the audit trail starts with the first real change.
- **Salary corrections require a `correctionReason`.** It's stored in the audit row, because changing history should always say why.
- **Unchanged updates are no-ops.** They don't bump the version or write an audit row, so the audit trail stays meaningful.

### Decisions made while reviewing AI output

- **CSV upload is CSV text in a JSON body, not multipart.** The API stays JSON-only, so the CSRF defence is uniform and no upload library is needed. The 4 MB file cap still fits serverless body limits. Architecture §7 was updated.
- **Native `<select>` for filters** instead of a custom combobox. It gives the most reliable keyboard and screen reader behaviour for little code.
- **Money is formatted straight from the server's decimal string**, using as many decimals as were sent. A unit test proves `999999999999999.99` is shown exactly where a float would round it.
- **In pay-currency mode, the analytics chart compares groups within one selected currency.** Cross-currency bars would mislead; the table still lists every group and currency.
- **End-to-end tests run on their own `acme_e2e` database and ports** so they never change development data. This avoids repeating the earlier mistake where a smoke test polluted the dev database.
- **Read-only users never see write actions.** The API enforces the role regardless, and the tests check both.
